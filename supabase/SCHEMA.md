# Cardtly database schema

Generated by `npm run schema` from the live database. Do not edit by hand.

## Read this before changing the database

The files in `supabase/migrations` are **not** a complete record of this
database. Much of it was changed directly in the Supabase dashboard, so a
column, trigger or policy can exist here and appear nowhere in the repo.
Check this file before assuming a column does not exist.

**What this file covers:** every table, column, type and default, plus the
signatures of functions exposed over the API.

**What it does not cover:** triggers, RLS policies, indexes, check
constraints and function bodies. PostgREST cannot see them. For those you
need a direct database connection:

```
supabase link --project-ref <ref>
supabase db dump --schema public > supabase/schema.sql
```

That gap has already caused one production incident: a trigger forces
`cards.archived = true` when `assigned_user_id` is null, and an RLS policy
hides archived cards from the public, so a card 404s for every visitor while
the dashboard still shows it as healthy. Neither is visible from this file.
